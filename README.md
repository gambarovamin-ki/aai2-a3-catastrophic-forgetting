# Catastrophic Forgetting and Task Similarity

AAI2 Practicals, Topic A3 — TH Ingolstadt, Prof. Dr. Christian Nagel.

**Research question.** How does the *input* similarity between two
sequential tasks affect the amount of catastrophic forgetting, and does
Elastic Weight Consolidation reduce forgetting more than simple
experience replay as that similarity decreases?

Task A is standard MNIST. Task B is MNIST with the pixels inside a centred
square of side `PS` permuted, so `PS` runs from 0 (identical tasks) to 28
(fully permuted) and acts as a controlled similarity knob. Five conditions
are compared: naive sequential fine-tuning, joint training, an L2 penalty,
EWC, and experience replay.

## Repository structure

```
metrics.py                  metric definitions (forgetting, BWT, FWT,
                            intransigence), with formulas and sources
aggregate.py                results.csv -> per-run metrics -> seed summary
test_metrics.py             unit tests, values checked by hand
make_synthetic_results.py   invented data for testing the pipeline
report.qmd                  the scientific note (Quarto source)
references.bib              bibliography
requirements.txt            pinned environment
```

> This folder is the **evaluation layer**. The training code (data
> loading, the permutation, the model, the five conditions) lives
> alongside it in the team repository and writes the `results.csv` this
> code consumes.

Python 3.11 or newer.

## Data

Both datasets are downloaded automatically on first run by
`torchvision.datasets`, into `./data/` (git-ignored):

- **MNIST** — 70,000 handwritten digits, 28×28 greyscale, 10 classes.
- **Fashion-MNIST** — same format and size, clothing instead of digits.
  Used for the single extra condition in which the inputs *and* the
  meaning of each class both differ.

No manual download is needed, and no data is committed to the repository.
The permutation is generated from a fixed seed, so the task pair is
identical on every machine.

## Running it

```bash
python test_metrics.py                      # check the formulas
python make_synthetic_results.py            # invented data, testing only
python aggregate.py SYNTHETIC_results.csv   # exercise the pipeline
python aggregate.py results.csv             # the real run
quarto render report.qmd                    # -> report.pdf
```

Every figure and table in the note is regenerated by these commands from
`results.csv`. Nothing is edited by hand.

## The results file contract

`aggregate.py` reads a CSV with exactly these columns:

| column | values | meaning |
|---|---|---|
| `method` | `naive`, `joint`, `l2`, `ewc`, `replay`, `random_init` | which condition |
| `pair` | `permuted`, `fashion` | which task pair |
| `ps` | 0, 8, 12, 16, 20, 24, 28 (`-1` for `fashion` and `random_init`) | side of the permuted square |
| `seed` | integer | random seed for this run |
| `after_task` | 0, 1, 2 | 0 = untrained, 1 = after Task A, 2 = after Task B |
| `eval_task` | 1, 2 | 1 = evaluated on Task A, 2 = on Task B |
| `accuracy` | 0–100 | percentage |

One row per evaluation. Every run needs the four rows `(1,1) (1,2) (2,1)
(2,2)`. The `random_init` rows with `after_task=0` supply the
forward-transfer baseline; without them the code falls back to 10% (chance
for ten classes) and the FWT numbers are approximate.

## What gets reported

`metrics_summary.csv` holds mean and standard deviation across seeds for
every metric. Nothing from `metrics_per_run.csv` appears in the note on
its own — single-seed numbers are noise.

Every forgetting number is reported beside Task B accuracy. A method can
show zero forgetting simply by refusing to learn the new task;
`test_metrics.py` contains that case as an explicit test.

## Reproducibility

- Fixed seeds for both the pixel permutation and the weight initialisation.
- Pinned dependency versions in `requirements.txt`.
- Hyperparameters selected on a held-out validation split; the test set is
  evaluated once.
- Identical optimiser, learning rate, batch size and epoch budget across
  all five conditions.
- Sanity check: at `PS=0` the two tasks are identical, so forgetting must
  be approximately zero.

## A warning about the synthetic data

`make_synthetic_results.py` writes **invented numbers**. They exist so the
pipeline can be tested before any experiment has run. They are not
results, and must never appear in the note, the slides, or any figure
presented as a finding. Files it writes are prefixed `SYNTHETIC_`.
